## 2. Conflict Resolution
**Status**: PASS WITH KNOWN LIMITATIONS

### Evidence:
- **Authoritative Server Timestamp Policy**:
  - `SyncRepository.runSync()` uses remote server timestamps `updated_at` (TIMESTAMPTZ) returned from Supabase Postgres queries as authoritative.
- **Clock Skew Safety Threshold**:
  - Implemented clock skew protection check: `isLocalFutureSkewed = localTime > nowMs + 60000` (1 minute future threshold).
  - If a client device's clock is skewed into the future, the local state is flagged as skewed and remote server state automatically overrides it during Union Merge, preventing permanent record locking.
- **Timestamp Source Categorization**:
  - `local metadata`: `new Date().toISOString()` generated at repository layer for provisional local ordering.
  - `sync metadata`: ISO timestamps stored in IndexedDB.
  - `server authoritative timestamp`: `updated_at` columns generated by Postgres database and returned via Supabase JS Client query results.

## 7. Remaining Limitations
1. **Clock Skew Granularity**:
   - Clock skew threshold is set to 60 seconds. Minor clock drifts (< 60s) still rely on Last-Write-Wins (LWW) comparison between client ISO timestamp and server timestamp.
2. **Schema Versioning**:
   - Ordering is based on `updated_at` timestamps rather than monotonically increasing database revision sequence numbers.
